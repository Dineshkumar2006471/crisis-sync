# Lessons

- For Cloud Run frontend deploys, verify both build-time and runtime environment requirements. `NEXT_PUBLIC_*` values used by prerendered client pages must be present during `next build`, not only as Cloud Run runtime env vars.
- When a long-running deploy stalls or fails, inspect Cloud Build logs immediately and report the exact failing build step before continuing. That shortens the fix loop and keeps status updates concrete.
- When a frontend API route wraps an AI backend, measure real end-to-end latency before setting abort timeouts. A short timeout can silently replace valid AI analysis with fallback content and distort the user-visible incident record.
- Never feed UI hint text like `Panic type hint: security` into the same fallback classifier path used for the real guest report. If AI falls back, classify from the raw report text plus a separate optional hint so the hint does not falsely raise severity.
- For `gcloud run deploy` and `gcloud run services update`, verify Cloud Run env vars after deployment. PowerShell argument formatting can collapse multiple env assignments into one malformed value and disable live AI initialization.
- When a client workflow writes to a secondary Firestore collection like `logs`, add and verify rules for that collection at the same time as the UI change. Incident actions can appear broken even when the primary document update is valid if the audit-log write is denied.
- Do not fall back to synthetic map coordinates for live operations screens. If an incident lacks GPS coordinates, show that location data is unavailable and push the reporting flow to capture real coordinates instead of rendering fake markers.
- When modernizing Google Maps, do not combine `mapId` with inline `styles`, and do not leave deprecated `google.maps.Marker` usage in incident-critical screens. Those warnings hide real operator errors in the console and make map debugging harder.
- Never treat cached browser session data as an auth bypass unless a deliberate test flag is enabled. Otherwise localStorage can become an unintended privilege path before Firebase auth finishes validating the real user.
- When Firestore rules restrict records by hotel or tenant, the client query must include the same tenant filter. A permissive-looking collection query can still fail entirely because Firestore evaluates whether the whole result set is provably allowed.
- When users ask for a high-end desktop-first redesign, do not ship a simplified or utilitarian landing pass first. Start directly with a strong typography-led art direction, concept-accurate imagery, and polished CTA hierarchy, then verify responsiveness as a secondary step.
